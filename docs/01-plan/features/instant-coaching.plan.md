# instant-coaching Plan

## Executive Summary

| 관점 | 내용 |
|------|------|
| **문제** | 사용자가 발언 후 12턴 완주까지 기다려야 피드백을 받을 수 있어, 즉각적 학습 기회를 놓침 |
| **솔루션** | 채팅 입력 영역에 "즉시 코칭" 버튼 추가, 마지막 1~2턴을 경량 AI 분석하여 긍정/부정 영향과 대안을 즉시 표시 |
| **기능/UX 효과** | 매 발언이 학습 기회가 되어 훈련 효과성 극대화, 대화 몰입을 깨지 않는 접기/펼치기 카드 UI |
| **핵심 가치** | 기존 "훈련 → 나중에 리포트" 모델에서 "실시간 코칭" 모델로 전환, 학습 루프 단축 |

---

## 1. 배경 및 문제 정의

### 현재 상태
- Simulation 화면에서 3턴마다 신뢰도 점수가 자동 갱신됨 (숫자 + 이벤트 로그)
- SOS 시스템은 "앞으로 뭘 할까?" 형태의 미래 지향적 조언
- 최종 피드백(Feedback 화면)은 12턴 완주 후에만 접근 가능
- **갭**: 사용자가 "방금 내가 한 말이 어떤 영향을 끼쳤는지" 즉시 알 수 있는 방법이 없음

### 해결할 문제
- 발언 직후 긍정적/부정적 영향을 즉시 확인하고 싶은 사용자 니즈
- 기존 SOS(미래 조언)와 다른 "과거 평가" 관점의 코칭 부재

## 2. 목표

| 목표 | 측정 기준 |
|------|----------|
| 발언별 즉시 피드백 제공 | 코칭 버튼 클릭 후 3초 이내 결과 표시 |
| API 비용 최소화 | 기존 scoreTrustLevel 대비 토큰 50% 이하 |
| 대화 몰입 유지 | 코칭 카드가 접기/펼치기 방식, 대화 흐름 방해 최소화 |
| 기존 기능과 충돌 없음 | 3턴 자동 점수, SOS 시스템 그대로 유지 |

## 3. 기능 상세

### 3.1 즉시 코칭 버튼
- **위치**: 채팅 입력 영역 우측, 전송 버튼 옆
- **아이콘**: 전구(💡) 또는 Material Icon `tips_and_updates`
- **활성 조건**: 최소 1턴 이상 대화 진행 후 (사용자 메시지 + AI 응답 존재 시)
- **비활성 상태**: 로딩 중, AI 응답 대기 중

### 3.2 즉시 코칭 카드 UI
- **표시 위치**: 가장 최근 AI 응답 메시지 아래에 인라인 표시
- **레이아웃**:
  ```
  ┌─ 💡 즉시 코칭 ──────────────────────┐
  │ ✅ 긍정 영향: (1문장)                │
  │ ⚠️ 리스크: (1문장)                   │
  │ 📊 예상 신뢰 변화: +N / -N           │
  │ 💬 더 나은 표현: "..."               │
  │ 🎯 핵심 팁: (1문장)                  │
  │                           [접기 ▲]  │
  └─────────────────────────────────────┘
  ```
- **접기/펼치기**: 토글 방식, 새 코칭 요청 시 자동 펼침
- **스타일**: 기존 SOS 카드와 유사하되, 보라색(SOS)과 구분되는 앰버/골드 톤

### 3.3 경량 AI 분석 (핵심)
- **입력**: 마지막 사용자 메시지 1개 + AI 응답 1개 + 시나리오 컨텍스트
- **출력 구조**:
  ```typescript
  interface InstantCoachingResult {
    positiveImpact: string;      // 긍정적 영향 (1문장, 60자 이내)
    negativeRisk: string;        // 부정적 영향/리스크 (1문장, 60자 이내)
    estimatedTrustDelta: number; // 예상 신뢰 변화 (-10 ~ +5)
    betterAlternative: string;   // 더 나은 표현 제안 (직접 인용 형태)
    tip: string;                 // 핵심 코칭 팁 (1문장, 40자 이내)
  }
  ```
- **프롬프트 전략**: 경량 시스템 프롬프트 (500토큰 이내) + 최소 컨텍스트
- **모델**: `gemini-2.5-flash` (기존과 동일)
- **temperature**: 0.3 (일관성 우선)

### 3.4 SOS와의 차별화

| 항목 | SOS (기존) | 즉시 코칭 (신규) |
|------|-----------|-----------------|
| 관점 | 미래 ("다음에 뭘 할까?") | 과거 ("방금 한 말은?") |
| 출력 | 통찰 + 제안 + 매직 프레이즈 3개 | 영향 분석 + 대안 + 팁 |
| 입력 범위 | 최근 10개 메시지 | 최근 2개 메시지 (1턴) |
| 토큰 비용 | 높음 (~2000 토큰) | 낮음 (~500 토큰) |
| 색상 톤 | 보라색 | 앰버/골드 |

## 4. 기술 설계 방향

### 4.1 서비스 레이어
- `trustLevelService.ts`에 `getInstantCoaching()` 메서드 추가
- 별도 경량 시스템 프롬프트 (기존 141줄 프롬프트와 별개)
- JSON 스키마 응답 강제 (`responseMimeType: 'application/json'`)

### 4.2 UI 레이어
- `Simulation.tsx`에 상태 추가: `instantCoaching`, `isCoachingLoading`, `showCoaching`
- 코칭 버튼 컴포넌트: 입력 영역 내 배치
- 코칭 카드 컴포넌트: 메시지 영역 내 인라인 렌더링

### 4.3 API 비용 최적화
- 입력: 최근 2개 메시지만 전송 (vs SOS의 10개)
- 시스템 프롬프트: 500토큰 이내 경량화
- 출력: 5개 필드, 각 60자 이내 → 약 100~150 출력 토큰
- **예상 호출당 비용**: 입력 ~800토큰 + 출력 ~150토큰 ≈ 950토큰/호출

## 5. 범위

### 포함
- 즉시 코칭 버튼 UI
- 즉시 코칭 카드 UI (접기/펼치기)
- `getInstantCoaching()` 서비스 함수
- 경량 프롬프트 설계

### 제외
- 코칭 히스토리 저장 (향후 확장)
- Feedback 화면과의 연동 (향후 확장)
- VoiceSimulation 화면 적용 (향후 확장)

## 6. 리스크

| 리스크 | 확률 | 대응 |
|--------|------|------|
| API 응답 지연 (>3초) | 중 | 로딩 스피너 + 타임아웃 5초 설정 |
| 대화 몰입 방해 | 저 | 접기/펼치기, 자동으로 접히지 않음 |
| 기존 3턴 점수와 혼동 | 중 | "예상" vs "확정" 라벨 명확 구분 |
| API 비용 증가 | 중 | 수동 트리거(버튼), 자동 호출 아님 |
