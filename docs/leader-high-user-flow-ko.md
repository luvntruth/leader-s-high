# 리더스하이 사용자 흐름 한 장 정리

## 1) 한눈에 보는 전체 흐름 (v2)

```text
[유입]
광고 / 링크 / 검색 / 공유
   ↓
[랜딩]
서비스 소개 확인
   ↓
[온보딩]
무료 시나리오 3개 중 하나 선택
   ↓
[체험 시작]
가입 없이 첫 시뮬레이션 시작
   ↓
[시뮬레이션]
AI 팀원과 대화 연습
   ↓
[피드백]
간략 리포트 무료 확인
   ↓
[확장 선택]
전체 리포트 보기 / 다음 시나리오 계속하기 / 기록 저장하기
   ↓
[가입]
계정 생성 후 기록 저장 및 추가 기능 접근
   ↓
[업그레이드/결제]
필요할 때만 상세 리포트 또는 플랜 결제
   ↓
[계속 사용]
다음 시나리오 도전 / 기록 확인 / 업그레이드
```

---

## 2) 사용자 입장에서 보면 이렇게 움직입니다

### A. 처음 들어오는 단계
- 사용자는 보통 **랜딩 페이지**에서 시작합니다.
- 여기서 보는 것:
  - 리더스하이가 뭔지
  - 왜 필요한지
  - 무료로 체험 가능한지
- 목표:
  - **"한 번 해볼까?"** 를 만들기

### B. 체험 시작 단계
- 사용자는 **온보딩**에서 무료 시나리오 3개를 봅니다.
- 여기서 중요한 것은 **가입 없이 바로 시작 가능**하다는 점입니다.
- 목표:
  - **첫 시뮬레이션 시작 버튼을 누르게 만들기**

### C. 실제 사용 단계
- 사용자는 **Setup → Simulation**으로 들어갑니다.
- 여기서 팀원 캐릭터 정보와 상황을 보고 대화를 시작합니다.
- 목표:
  - **끝까지 체험하게 만들기**

### D. 결과 확인 단계
- 시뮬레이션이 끝나면 **Feedback**으로 갑니다.
- 여기서 먼저 보여줘야 하는 것은 **간략 리포트**입니다.
- 예:
  - 내 대화 요약
  - 잘한 점 1~2개
  - 아쉬운 점 1~2개
  - 다음 대화에서 바로 고칠 포인트
- 목표:
  - **"이거 가치 있네"** 를 먼저 느끼게 만들기

### E. 확장 선택 단계
- 간략 리포트를 본 사용자는 다음 선택을 합니다.
  - **전체 리포트 보기**
  - **다음 시나리오 계속하기**
  - **기록 저장하기**
- 여기서 핵심은, 사용자가 이미 가치를 본 뒤에 다음 행동을 고르게 하는 것입니다.
- 목표:
  - **가입/확장 행동이 자연스럽게 이어지게 만들기**

### F. 가입 단계
- 가입은 더 이상 결제 직전의 장벽이 아닙니다.
- 가입 이유는 분명해야 합니다.
  - 기록 저장
  - 이전 리포트 비교
  - 다음 시나리오 이어서 사용
  - 상세 리포트 접근
- 목표:
  - **가입을 귀찮은 절차가 아니라 가치 확장 단계로 느끼게 만들기**

### G. 업그레이드/결제 단계
- 결제는 체험 직후 바로 강요하지 않습니다.
- 사용자가 간략 리포트를 보고 가치에 공감한 뒤,
  - 상세 리포트
  - 추가 시나리오
  - 반복 연습
  - 기록 저장/비교
  같은 확장 이유가 생겼을 때 제안합니다.
- 목표:
  - **결제를 압박이 아니라 자연스러운 다음 단계로 만들기**

### H. 계속 사용 단계
- 사용자는 다음 시나리오로 넘어가거나
- 홈으로 돌아가거나
- 기록/인사이트를 확인합니다.
- 목표:
  - **한 번 체험으로 끝나지 않게 만들기**

## 3) v2에서 바뀐 핵심 원칙

### 원칙 1. 첫 체험 뒤에는 돈보다 가치가 먼저다
- 사용자가 첫 경험 직후 바로 돈을 내야 하면 이탈 가능성이 커집니다.
- 따라서 **간략 리포트는 무료로 먼저 보여줍니다.**

### 원칙 2. 가입은 결제 장벽이 아니라 확장 단계다
- 기존에는 구매를 누르면 회원가입이 끼어들어 흐름을 끊었습니다.
- v2에서는 가입을 **기록 저장/상세 리포트 접근/추가 사용을 위한 단계**로 옮깁니다.

### 원칙 3. 상세 리포트나 플랜 결제는 나중에 제안한다
- 체험 직후 바로 3,900원 결제를 강하게 미는 구조는 초기 실험에 불리합니다.
- 먼저 가치를 보여주고, **더 깊게 보고 싶을 때 결제**하게 해야 합니다.

## 4) 보스가 사업적으로 봐야 할 핵심 질문

### 질문 1. 랜딩을 본 사람이 체험을 시작하나?
- 랜딩은 좋은데 클릭이 없으면
  - 메시지 문제
  - CTA 문제

### 질문 2. 체험을 시작한 사람이 끝까지 가나?
- 중간에 많이 빠지면
  - 온보딩 문제
  - 시뮬레이션 진입 장벽 문제
  - 체험 자체가 어렵거나 길 수 있음

### 질문 3. 끝까지 한 사람이 간략 리포트에서 다음 행동을 하나?
- 여기서 안 움직이면
  - 리포트 가치 전달 문제
  - 확장 CTA 문제
  - 가입 이유가 약할 수 있음

### 질문 4. 가입한 사람이 실제 결제까지 가나?
- 여기서 안 움직이면
  - 상세 리포트/플랜 가치가 약함
  - 가격/오퍼 문제
  - 결제 설계 문제

## 5) 지금 기준으로 가장 중요한 숫자 4개

1. **랜딩 → 체험 시작률**
   - 들어온 사람 중 몇 명이 실제로 시작했는가

2. **체험 시작 → 완료율**
   - 시작한 사람 중 몇 명이 끝까지 갔는가

3. **완료 → 다음 행동률**
   - 간략 리포트를 본 사람 중 몇 명이
     - 전체 리포트 보기
     - 기록 저장
     - 다음 시나리오 진행
     로 이어졌는가

4. **가입 → 결제 전환율**
   - 가입한 사람 중 몇 명이 실제로 상세 리포트 또는 플랜 결제까지 갔는가

## 6) 보스용 한 줄 해석

> 리더스하이 v2는
> **사람을 데려오고 → 무료 체험시키고 → 가치부터 보여주고 → 그 다음 가입/확장/결제로 이어지게 만드는 구조**입니다.

즉 지금 우리가 봐야 할 것은:
- 어디서 들어오고
- 어디서 빠지고
- 어디서 가치가 느껴지고
- 어디서 돈이 생기는지

이 4가지입니다.
